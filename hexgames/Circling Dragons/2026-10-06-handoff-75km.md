## How the pipeline is scale-dependent

All in `map_graphics/xml/tools/cd/` (README there). Read `lattice.py` first; it is about 220 lines.

- `lattice.py`: `HEX_KM = 100.0`, `SIZE = 46.0` (circumradius px), `COLS, ROWS = 35, 34`,
  `XMIN_KM, YMAX_KM = -1700.0, 1770.0`, `MARGIN`. Column pitch in km is `1.5 * HEX_KM / sqrt(3)` (86.6 at
  100 km, 65 at 75), row pitch is `HEX_KM`. Make the scale a parameter: read `CD_HEX_KM` from the
  environment (default 100), keep the same geographic extent, so `COLS = round(35 * 86.6 / pitch)` = 47 and
  `ROWS = round(34 * 100 / HEX_KM)` = 45 at 75 km. Keep `SIZE = 46` so counters stay the same pixel size;
  the sheet grows to about 3,340 x 3,800 px. Add helpers that evaluate the lattice at a given scale
  (`hex_of_ll(lat, lon, hex_km=...)` or a small class) because rescaling hand data needs both lattices.
- `stage1_geo.py` (Natural Earth rasterisation; needs `tools/cd/ne/*.geojson`, 17 MB, not in the repo;
  I had NOT yet checked whether the files are still on disk; if they are missing, downloading them is a
  file download and Ben must approve it; the URLs are in the README), `stage2_elev.py` (ETOPO1 through
  api.opentopodata.org, resumable, cached per hex id; at 75 km about 1,560 land hexes x 19 points =
  30k points; the public API allows 100 locations per request, 1 request per second, 1,000 requests a
  day, so about 300 requests, 5 to 10 minutes; check how the script batches), `stage3_rivers.py`
  (snaps rivers to lattice vertices; waypoints `YELLOW_1938`, `YANGTZE_ESTUARY`, `CUTS` are lat/lon, fine),
  `stage4_terrain.py` (classes from per-hex elevation statistics plus hand rulings).
- Cache files `geo_hex.json`, `elev_hex.json`, `rivers.json`, `terrain_hex.json` are keyed by hex id
  (`terrain_hex.json` values are dicts with `cls`, `mean`, `std`, `max`, `land`, `lake`, `country`).
  Give the 75 km run its own files, e.g. suffix `-75`, chosen from the same environment variable.
- `cd_data.py`: places, rails, roads, tracks, labels, polygons (Manchukuo, Mengjiang, DESERT, STEPPE,
  MARSH) are lat/lon and scale freely. Hex-id-keyed data must be rescaled: `RANGES` (named ranges as hex
  lists), `LAKES`, `REDOUBT_HEXES = "2811 2911 2910 3009 3010"`, `PLACE_HEX` (five pins: baoqing 1326,
  hanzhong 0820, kaifeng 1718, suizhong 2211, taiyuan 1415; drop them at 75 km, they fixed 100 km
  collisions). Rescale a hex list by taking every 75 km hex whose centre falls in a listed 100 km hex;
  that keeps the rulings and leaves no gaps. Check `RAIL_EXITS` and `ROAD_EXITS`, which I did not read;
  they may be edge hex ids.
- `stage4_terrain.py` thresholds were tuned at 100 km on `std` and `mean`; a 75 km hex has less relief
  variance, so the 75 km map may come out flatter. Compare the class shares of the two sheets (100 km:
  steppe 102, mountain 158, marsh 19, broken 220, clear 173 of 672 in play) and adjust if needed.
- `build_cd.py`: `VERSION = 3` is the standard; panels are placed at absolute pixel coordinates (NW
  panels x 70, y 70..540; soviet-east x 2240, y 790; hump x 70, y 2660; SE column `X, Y, W = 1900, 1895,
  590`). Scale the panel x and y by the sheet size ratio (about 1.31, 1.33) and leave w, h; the quiet
  corners are the same geography. Output name `circling-dragons-75.xml`, sheet id `circling-dragons-75`,

- `network_check.py`: add `"circling-dragons-75": CD_PROFILE` to the id map. Run

## The illustration machinery

`map_graphics/xml/tools/cd/illustrate.py` draws a crop of a sheet's reference SVG with counters from
`unit_graphics/xml/circling-dragons.xml` through `counters2svg.Renderer.face_svg` (100 x 100 frame),
plus arrows, bursts, notes, a title box with counters, a legend. Pictures are dicts in `PICTURES`
(`name, crop, size, title, sub, title_counters, items, legend`); `items` is a function returning the
list of drawn things; `stack(hex, [ids])`, `arrow([hexes], colour, label, at, dx, dy, anchor)`,
`burst(hex, label)`, `note(hex, text, dx, dy)`. `H(lat, lon)` gives the hex id of a point, `C(hex)` its
centre. Add a `--sheet 75` option: set `CD_HEX_KM` before importing `lattice`, load
`circling-dragons-75.svg`, write to `Circling Dragons/illustrations/75/`. Build the maneuver pictures
from lat/lon with `H(...)`, not hard-coded ids: Yueyang 29.37N 113.10E, Miluo 28.80N 113.07E, Changsha
28.20N 112.97E, Liuyang 28.15N 113.63E, Ningxiang 28.25N 112.55E, Yiyang 28.55N 112.33E, Pingjiang
28.70N 113.58E, Hengshan 27.23N 112.87E, Hengyang 26.89N 112.61E, Leiyang 26.42N 112.86E, Shaoyang
27.24N 111.47E, Qiyang 26.58N 111.85E, Chaling 26.79N 113.54E. Use tight crops (about nine hexes
square) so the counters read; counter size 60 to 66 px. Counter ids: Japanese divisions `jp-d3`,

  `\\L` arrived as `\L`.

  `-jobname=<name>-new` and `mv -f` over the original, which worked.

  not checked but the counter XML carries a comment anyway.
- hexcounters: colour ids, style ids, counter ids and sheet ids share one xs:ID space.
- hexsheet: hexview draws panel children kind by kind, the reference renderer in document order, so the
  builder groups them by kind.
